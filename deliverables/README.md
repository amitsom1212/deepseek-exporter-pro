# 交付物说明

本目录是「DeepSeek 对话导出 Pro」的全部成品，当前版本 **v1.1.3**。

## 1. 浏览器扩展（主交付）

| 文件 | 说明 |
| --- | --- |
| `deepseek-exporter-pro-v1.1.3.zip` | **推荐**。解压后得到扩展目录 |
| `../dsx-pro/dist/` | 已构建好的扩展目录，可直接加载，无需解压 zip |

**安装**：`chrome://extensions/` → 打开「开发者模式」→「加载已解压的扩展程序」→
选择**根层直接有 `manifest.json` 的那一层**（即解压后的文件夹本身，或 `dsx-pro/dist`）。

> ⚠️ **不要加载 `dsx-pro` 源码工程目录**：它根层没有 `manifest.json`，而且 `node_modules` 里有
> `_stream_duplex.js` 这类以 `_` 开头的文件——Chrome 把 `_` 前缀视为系统保留，会直接拒绝加载整个扩展。

**升级**：请在扩展页点一下刷新按钮重新加载。

支持站点：`chat.deepseek.com`、DSH 本地界面（`http://127.0.0.1:3080`）。

## v1.1.3 修了什么（内联图片让 Word 里出现 base64）

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 选了「内联进 Markdown」后导出 Word，文档里出现一长串看不懂的字符（其实是 base64），图没嵌进去 | 内联模式下 markdown 的图片地址就是 `data:image/png;base64,…`，而 docx 的图片解析器只认远端 URL 和相对路径；解析失败就按占位提示把**整串地址当文字**写进了文档 | ①解析器最前面加 data URL 分支，直接解码嵌入；②占位提示不再输出原始地址（超长一律截断）——任何情况下都不会再往文档里灌 base64 |
| 内联模式下 `images/` 目录是空的，看着像丢图 | 内联模式的设计就是"单文件自包含"：图片写进 `.md` 正文，不再单独落文件 | 属预期行为。想要图片单独成文件，请选「存到子目录（推荐）」 |

## v1.1.2 修了什么（勾了「图片」却一张都没导出）

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 导出选项里勾了「图片」，但文档与 `images/` 子目录里都没有图片 | 图片检测只读了几个写死的字段（`files`/`file_list`/`attachments`），而站点已把图片挪进 `fragments`（如 `{type:'IMAGE', image:{...}}`）或改叫 `image_list` | 改为**深度扫描**整条消息：任意字段名、任意嵌套层级都能命中，并排除头像/图标等装饰图 |
| 正文里以 markdown 链接出现的图片，`.md` 里留的是会过期的远端链接 | 内联图片走的是"只给 Word 用"的另一条支路 | 内联图片与附件**统一走落盘流水线**：都存进 `images/`，并就地改写正文里的引用为本地路径 |
| 接口只给文字、不给上传图的地址时图就丢了 | 上传图有时只存在于页面 DOM | 加兜底：接口一张图都没给时，从页面 DOM 按「同角色第 n 条」补图；文字仍以接口为准（保留 LaTeX 原文） |
| 出问题时不知道图片藏在哪个字段 | 诊断只报选择器 | 诊断报告新增 `imageInfo`：多少条消息带图、样例地址、首条用户消息里"含 URL 的字段名"与嵌套数组路径 |

> 之前若为了不丢图而手动去页面扒图，现在重新导一次即可。

## v1.1.1 修了什么（授权文件夹目录重复嵌套）

授权了 `E:\考研\dsx笔记整理`，导出却落在 `E:\考研\dsx笔记整理\考研\dsx笔记整理\...`。

**根因**：文件路径被设计成「①里的下载目录相对路径 + 分类/会话/文件名」，落盘时又把这一整串塞进授权目录——于是"下载目录用的那串前缀"被叠加上去了。

**修法**：文件路径只表示「**导出根目录内**的相对路径」，由落盘目标决定前缀——

| 落盘目标 | 前缀 |
| --- | --- |
| 浏览器下载目录 | ① 里的相对路径（`singleFolder` / `batchFolder`） |
| 已授权真实文件夹 | ② 里新增的「授权文件夹内部子目录」（默认空 = 直接放在授权目录根下） |

两套前缀**互不叠加**。同时补了可见性：设置页 ② 新增「**实际写入位置预览**」，批量面板的「导出位置」同时列出两个目标，索引文件也回报真实落盘路径。

> 升级提醒：如果你之前为了规避重复嵌套，把 ① 里的相对路径清空了，现在可以填回来（它只在写下载目录时生效）。

## v1.1.0 修了什么 / 加了什么

**修复**

1. **消息正文全空** —— DeepSeek 把正文从 `content` 挪进了 `fragments[]`，旧代码读不到。
   现在两种形态都支持；接口结构再次变化时会**自动回退页面抓取**，不会再给你空白面板。
2. **诊断报告生成失败** —— 之前用的是「当前活动标签页」，而你是在设置页点按钮，
   于是它诊断了设置页自己。现在改为**显式选择要诊断哪个网页**。
3. **设置页初始化失败**（`(selected || []).slice is not a function`）—— 参数类型传错。
4. **扩展装不上（不是 UTF-8 编码）** —— 依赖里内嵌了 Chrome 拒绝的 `U+FFFF` 字符；
   现在构建期会校验并直接拦下。
5. **加载扩展报 `_cp.mjs` 是保留名** —— 加载的应是 `dist`，源码目录永远不行
   （`node_modules` 里有 `_` 开头的文件）。现已加构建期保留名校验，并在产物里放《如何安装.txt》。
6. **页面已打开时扩展无响应** —— 消息监听器注册时机错误 + 已打开的标签页不会自动注入内容脚本。
7. **DSH 识别不了** —— 用了一个在隔离世界里读不到的页面全局变量；改为按端口 3080 认定。

**新增：AI 归类归档**

把「会话标题 + 开头约 900 字」发给你**自己配置的 OpenAI 兼容接口**，
判断是否知识答疑、属于哪个科目（数学 / 英语 / 政治 / 408 及其四个子类…），
按科目归档到不同文件夹。默认关闭；也可指向本地 Ollama / LM Studio 让内容不出本机。

## 第一次使用建议按这个顺序验证

1. 打开 `selftest-sample.docx`，确认公式在 Word 里可以点开编辑
2. 双击 `Markdown转Word-离线单文件.html`，随便粘一段带公式的 Markdown 试试
3. `chrome://extensions/` → **刷新扩展** → 打开 `chat.deepseek.com` 的一个对话 → 点「导出对话」
   - 面板顶部应显示「**数据来源：站点接口（公式为 LaTeX 原文…）**」且消息列表有内容
   - 若显示黄色「页面 DOM 抓取」，说明接口结构又变了（此时导出仍可用，但请把诊断报告发我）
4. 用真实文件夹归档：设置页 ② → 选择文件夹并授权 → 在「授权文件夹内部子目录」决定要不要再分一层
   → 下方「实际写入位置预览」会直接告诉你最终路径
5. 想用 AI 归类：设置页 ⑤ → 勾选启用 → 填 API Key（或选本地 Ollama 预设）→ 点「测试接口」→ 通了再「保存设置」
6. 若消息读不到或面板异常：设置页 → **⑥ 权限与诊断** → 在「**诊断目标**」下拉框里选中你的 DeepSeek 页面 → 点「诊断选中的页面」→ 复制报告发我
